# 组件重绘监测 - 实现规划

## 一、目标与范围

### 1.1 术语说明

| 概念 | 含义 | 监测价值 |
|------|------|----------|
| **Widget 重建 (Rebuild)** | 某 Widget 的 `build()` 再次被调用（父级重建、`setState`、`InheritedWidget` 变化等） | 高：直接对应不必要的重复构建、性能热点 |
| **RenderObject 重绘 (Repaint)** | `RenderObject.markNeedsPaint()` 导致该子树在下一帧参与绘制 | 中：更底层，与列表/动画卡顿相关 |

本功能**优先做 Widget 重建监测**。RenderObject 重绘可作为后续扩展。

### 1.2 设计原则：查询式、AI 友好

- **不做命令式 API**：不要求 AI 先 `start`、再记得 `stop`、再 `getReport`。
- **只做“问数据”**：AI 随时要当前状态就调 **Snapshot**，要最近 N 帧趋势就调 **Timeline**，要两段时期对比就调 **Diff**。
- **以帧为时间轴**：所有统计按 Flutter 的帧号对齐。

---

## 二、VM Service 设计（给 MCP 用的核心）

扩展前缀：`flutter_copilot.rebuild.*`。

### 2.1 Snapshot — 当前状态快照

**Extension**：`flutter_copilot.rebuild.snapshot`

**语义**：返回当前时刻的累计重建统计。

**返回示例**：`{ "status": "Success", "frame": 12345, "total": 9821, "top": [...], "hotspots": [...] }`

### 2.2 Timeline — 最近 N 帧的每帧重建数

**Extension**：`flutter_copilot.rebuild.timeline`，参数 `last`（默认 100）。

**返回示例**：`{ "status": "Success", "frames": [ { "frame": 12325, "count": 30 }, ... ] }`

### 2.3 Diff — 两段时期的对比

**Extension**：`flutter_copilot.rebuild.diff`，参数 `from`、`to`（帧号）。

**返回示例**：`{ "status": "Success", "fromFrame", "toFrame", "total", "top", "hotspots" }`

---

## 三、数据模型与后端实现要点

### 3.1 以“帧”为单位的环形缓冲

- 每帧结束（`addPostFrameCallback`）：把本帧内 `recordBuild()` 的累计写入帧记录；帧记录含 `frameId`、本帧 `totalCount`，以及 per-widget 计数（受 TopK 限制）。
- 环形缓冲：保留最近 M 帧（如 500），超过则覆盖最旧一帧。
- 全局累计：维护“自启动以来”的 `total` 和 `Map<widgetKey, count>`，用于 Snapshot。

### 3.1.1 每帧 per-widget 的 TopK 限制（必须）

- 每帧最多只保留 TopK 个 widget（按本帧 count 降序），例如 K = 50。
- 其余合并为 `"__other__"`，count = 本帧 total - TopK 项 count 之和。
- 配置建议：`FlutterCopilotConfiguration.rebuildTrackTopKPerFrame`（默认 50）。

### 3.2 Snapshot / Timeline / Diff 的数据来源

- Snapshot：`frame`、`total`、`top`、`hotspots` 从全局累计计算。
- Timeline：从环形缓冲取最近 `last` 条帧记录。
- Diff：从环形缓冲取 `[from, to]` 区间帧记录，合并 per-widget（含 `__other__` 跨帧相加）。

## 四、采集层：BuildOwner Hook + Tracker

### 4.1 统计入口（主方案：BuildOwner Hook）

- **无需业务侧包裹任何 Widget**。当 `FlutterCopilotConfiguration.enableGlobalRebuildHook` 为 true 时，[FlutterCopilotBinding](packages/flutter_copilot_claw/lib/src/binding/flutter_copilot_binding.dart) 注入 [CopilotBuildOwner](packages/flutter_copilot_claw/lib/src/binding/copilot_build_owner.dart)。
- [CopilotBuildOwner] 继承 `BuildOwner`，重写 `scheduleBuildFor(Element element)`：在调用 `super.scheduleBuildFor(element)` 前，用 `element.widget.runtimeType` 与 `element.widget.key` 调用 `WidgetRebuildTracker.instance?.recordBuild(...)`。
- 每次 Element 被标记为 dirty 并加入本帧构建队列时会被记录一次，与实际执行 rebuild 一一对应。

### 4.2 配置与 Release

- `enableGlobalRebuildHook`：为 true 时创建 Tracker 并注入 CopilotBuildOwner；为 false 时不创建、不注入，扩展返回未启用或空数据。Release 下建议设为 false。

## 六、实现步骤（建议顺序）

1. CopilotBuildOwner：scheduleBuildFor 中 recordBuild。
2. FlutterCopilotBinding：initInstances 中创建并注入 CopilotBuildOwner，override buildOwner getter。
3. WidgetRebuildTracker：保持现有或按文档补齐 timeline/diff 环形缓冲与 TopK。
4. 注册 VM Service Extension：snapshot（已实现）；timeline、diff 按需。
5. 文档与 Example：演示页采用定时器模拟错误重绘，由 BuildOwner Hook 自动统计。

---

## 七、风险与注意点

- **BuildOwner 替换**：依赖对 `buildOwner` getter 的 override，与 Flutter 版本兼容性需注意；BuildOwner API（如 scheduleBuildFor、onBuildScheduled）在 Flutter 升级时可能变化。
- **多 BuildOwner**：仅替换 Binding 的默认 buildOwner，其它子树若使用独立 BuildOwner 不会被统计，属于预期。
- **每帧 TopK + __other__（必做）**：ListView + 1000 item 等场景下，每帧只保留 TopK（如 50）条，其余归为 `__other__`，避免内存爆炸。
- **环形缓冲容量**：帧数 M 与每帧 per-widget 条数（K+1）已设上限；diff 的 from/to 超出缓冲范围时返回错误或仅返回有数据的区间。
- **性能**：recordBuild 为 O(1)；每帧结束时合并与落盘；getSnapshot/getTimeline/getDiff 为只读。
- **Release**：通过配置关闭后，不记录、不分配环形缓冲，扩展可返回“未启用”。

---

## 八、总结

- **API**：Snapshot / Timeline / Diff 三个查询式扩展，无 start/stop。
- **采集**：**BuildOwner Hook**（CopilotBuildOwner.scheduleBuildFor），无侵入。
- **后端**：按帧聚合 + 环形缓冲（每帧 per-widget 受 TopK 限制），支持 snapshot 及后续 timeline、diff。
