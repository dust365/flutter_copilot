# Flutter Copilot 演讲稿 v3 优化 Todo

## 目标
把 v2 项目介绍稿，整理成一版更适合现场演讲的 v3 结构稿：重点更集中、口语感更强、节奏更清晰、PPT 配图需求更明确。

---

## 一、整体改造方向

### 1. 收内容，不再继续加内容
- 重点不是补更多原理说明，而是把已有信息收束成更强的现场表达。
- 优先保证“好讲、好记、有画面感”。

### 2. 从“文章感”改成“演讲感”
- 减少过长书面句。
- 强化短句、停顿句、总结句。
- 每一节都尽量回答一个明确问题，而不是平均铺开信息。

### 3. 强化主线
建议整场分享围绕三句话展开：
- AI 不该只会写代码，还应该会操作 App。
- Flutter Copilot 的关键，不是脚本点击，而是把 AI 接进 Flutter 运行时。
- 真正有价值的不是某一个工具，而是 AI 进入完整工作流。

---

## 二、各部分优化 Todo

### 1. 开场：保留主线，增强口语感
- 保留“为什么浏览器有，Flutter 没有”这个切入点。
- 保留“AI 写代码快，但看不到 App”的核心痛点。
- 适当压缩解释性句子，让开场更快进入主题。

### 2. 效果演示：重写成更有递进的三段
当前问题：
- 三个场景说明清楚，但冲击力还不够。
- 标题偏长，像文档标题。
- 三段之间递进关系不够明显。

优化动作：
- 改成三段递进：
  1. AI 自己跑完一个表单流程
  2. AI 一边改 UI，一边对照效果继续修
  3. AI 直接抓日志定位异常
- 每段统一结构：
  - 以前怎么做
  - 现在怎么做
  - 本质上省掉了什么
- 用一句话收束成“AI 不只是读代码，而是在读运行中的 App”。

### 3. 技术揭秘：压缩科普，突出差异化
当前问题：
- MCP 和 VM Service 两段偏百科化。
- 一些实现细节对现场听众不是重点。
- 项目差异点还不够突出。

优化动作：
- 技术部分收成三件事：
  1. 三层架构
  2. 两个关键协议
  3. 为什么不是坐标点击，而是语义化操作
- 弱化“14 个 Extension”“完整协议定义”等细节。
- 强化一句核心表达：
  - 这不是自动点屏幕，而是把 AI 接进 Flutter 运行时。

### 4. 接入指南：降低心理门槛
当前问题：
- 内容实用，但略像安装文档。
- 缺少“其实没那么重”的感受强化。

优化动作：
- 开头先明确：接入没有想象中重。
- 保留三步法：
  1. App 内初始化 Binding
  2. App 外启动 MCP Server
  3. Agent 侧完成 MCP 配置
- 最后强调最佳实践：
  - 关键元素加 ValueKey<String>
  - 先从核心流程接入
  - 先定位成开发阶段效率工具

### 5. 提效对比：保留框架，弱化过满结论
当前问题：
- 表格结构是好的，但部分数据还是示意值。
- “整体提升 30%~40%”现在略显过实。

优化动作：
- 保留指标维度：
  - 单次验证耗时
  - 问题定位耗时
  - 人工参与次数
  - 反馈闭环时长
- 把结论改成更稳健表达：
  - 在高频验证和排查场景里，效率提升非常明显。
- “接入团队”补充成场景化表述，而不是简单名单。

### 6. 价值升华：大幅压缩，保留最有力量的部分
当前问题：
- 第六部分内容最好，但明显过长。
- 方法论、个人故事、价值启发都挤在一起，结尾容易失焦。

优化动作：
- 压缩成三个小节：
  1. AI 进入工作流，而不只是写代码
  2. 高频、重复、可验证的问题最适合交给 AI
  3. 每个团队都可以围绕自己的工作流做 skills / MCP / 工具链
- “我是怎么从探索到落地的”保留短版故事，不再展开成长篇经历。
- 把结尾收得更短、更有力量。
